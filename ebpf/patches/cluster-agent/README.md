# Cluster agent patches

These patches apply to coroot-cluster-agent v1.11.9 in both image builders.

Upstream requires PostgreSQL 10 or newer since v1.11.5, including for poolers reporting a PostgreSQL-compatible server version. Older targets produce a scrape error and no longer collect query, replication or size metrics. Patch `002` retains the existing collection scope with the updated `getWraparoundStats(ctx)` call. The new `DISABLE_KUBERNETES` option is left at its upstream default (`false`).

Upstream v1.11.9 moves the bundled `redis_exporter` from v1.61.0 to v1.97.0. It reports more metrics from the `INFO` reply the agent already fetched, mostly for Redis 7 and 8 and for Valkey, so Redis targets produce more series than on v1.11.5. `redis_instance_info` gains a `master_replid` label, whose value changes when a replica is promoted. No patch narrows this: the metrics come from data that was already collected.

* `001`: omit the Postgres startup `statement_timeout` parameter, which poolers can reject. The agent still uses context deadlines for its queries. Upstream has no flag or environment variable for omitting the startup parameter; `PGOPTIONS` does not override an explicit DSN parameter.
* `002`: preserve the existing database and Kubernetes collection scope. Skip the new MongoDB server-status, current-operation, profiler, replica-config and oplog scans; MySQL active-statement, lock-wait, transaction, InnoDB counter, binlog and group-replication queries; Postgres checkpoint, WAL, wraparound, table-stat and vacuum-progress queries; and the new Argo CD, CloudNativePG and Percona resource watchers. Skip the Redis and Valkey command-log queries (`COMMAND INFO COMMANDLOG`, `COMMANDLOG LEN`, `CONFIG GET commandlog-*`) that the bundled `redis_exporter` runs by default since upstream v1.11.9. Keep Flux watchers and existing database status, replication, query and size metrics. Additional counters derived from already-collected data remain available.
* `003`: guard the nil change-emitter interface when schema tracking is disabled. Up to v1.11.7, upstream passed a typed nil pointer to database constructors, which enabled schema tracking and could panic when a change was emitted. Since v1.11.8 upstream only sets the emitter in the exporter options when tracking is enabled, so this patch now only adds a regression test for that behaviour.
* `004`: omit the checkpoint and WAL-archive counters whose collection is disabled by patch `002`, rather than emit unobserved zeros. Removes `pg_checkpoints_scheduled_total` (timed and requested), `pg_checkpoints_total`, `pg_restartpoints_total`, `pg_buffers_written_total`, `pg_wal_archived_segments_total` and `pg_wal_archive_failures_total`. Keep the independently collected replication LSN metrics and existing database health, query and size metrics.

Runtime launcher scripts set `TRACK_DATABASE_BLOAT=false`, `PROFILES_SCRAPE_INTERVAL=0s`, `COLLECT_KUBERNETES_EVENTS=false` and `KUBE_STATE_METRICS_MIN_AGE=0s`. Keep `TRACK_DATABASE_SIZES=true` for database size metrics. Only set `TRACK_DATABASE_CHANGES=false` on images with the nil-emitter fix (patch 003 on v1.11.5, upstream from v1.11.8): both final images expose `CLUSTER_AGENT_VERSION` for this compatibility check. Older images must keep schema tracking enabled.

After applying the patches, run `go test -mod=readonly ./...` in the upstream checkout. The added tests check MongoDB commands and dashboard metrics, Kubernetes watcher scope, and the nil-emitter regression. Build with `CGO_ENABLED=0 GOTOOLCHAIN=local go build -mod=readonly .`.
